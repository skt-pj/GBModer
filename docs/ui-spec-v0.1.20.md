# GBModer UI仕様書 v0.1.20

## 1. 目的

本仕様は、2026-08-20に作成した「GBModer UI REVIEW — 2026.08」画像を一次資料として、GBModerの操作画面を現行の縦積みView UIから、Compose + Material 3を用いた階層的・スクロール可能・アダプティブなUIへ更新するための実装仕様を定義する。

フィルター、MediaProjection、Accessibility、ログ、フォント生成などの処理ロジックは変更対象外とし、操作画面の提示・入力・状態表示だけを置き換える。

## 2. 一次資料から読み取れる現状課題

1. 情報階層が平坦で、初回設定・通常設定・補助機能・説明が同一画面に同じ重さで並んでいる。
2. 画面全体がスクロール不可で、システムバーや大きな文字サイズで下部操作が隠れる可能性がある。
3. 「フィルター開始」と「停止」が同時に主要操作として表示され、現在状態に応じた主操作が明確でない。
4. 「ログ同期」「ADB手順」などの補助機能が主要設定と同列に見える。
5. タブレット・Foldableの横幅を活かしていない。
6. edge-to-edge / WindowInsets / 大文字サイズへの適応が設計に入っていない。

## 3. 画面全体構造

### 3.1 Phone / Compact

`Scaffold` を最上位に使用し、以下の順で配置する。

1. TopAppBar
2. 初回設定カード（必要時）
3. 表示モード
4. 解像度
5. 明るさ
6. コントラスト
7. ディザ
8. 詳細設定・診断（折りたたみ）
9. 主操作ボタン
10. ステータス表示

本文は縦スクロール可能とし、主操作ボタンはナビゲーションバーに隠れないこと。

### 3.2 Expanded / Tablet / Foldable

横幅が十分な場合は2ペインとする。

- 左ペイン: プレビューとGB(DMG)パレット表示
- 右ペイン: Phoneと同じ設定UI

2ペイン化しても機能・値・操作順序はPhone版と同一とする。

## 4. TopAppBar

- タイトル: `GBModer`
- 現在状態を小さな状態表示で示す: `停止中` / `実行中`
- 補助操作はoverflowへ集約可能とする。
- 状態表示は色だけに依存せず文字でも示す。

## 5. 初回設定カード

Accessibilityサービスが有効でない、または接続待ちの場合のみ強調表示する。

表示内容:

- 見出し: `初回設定`
- 説明: `ユーザー補助を有効にして、画面のテキストを取得します。`
- CTA: `ユーザー補助を有効化`

設定済みの場合、このカードは通常画面で主役にならないよう縮退または非表示にできる。

## 6. 表示モード

4択を `SingleChoiceSegmentedButtonRow` 相当の単一選択UIで表示する。

- GB
- GBC
- GBA
- DS

選択値と既存内部値の対応は変えない。

## 7. 解像度

1つの選択フィールドとして表示する。

選択肢は既存仕様を維持する。

- GB / 160×144
- GBC / 160×144
- GBA / 240×160
- DS / 256×192
- 端末比 / 25%
- 端末比 / 33%
- 端末比 / 50%
- 端末比 / 67%
- 端末比 / 75%
- スマホの元解像度

表示モードと解像度は独立値であり、組み合わせて適用する既存仕様を維持する。

## 8. 明るさ・コントラスト

- Material 3 Sliderを使用する。
- 現在値をラベル横へ常時数値表示する。
- 既存の内部範囲・初期値・変換式は変更しない。
- タッチ操作だけでなくTalkBack等で値を把握できること。

初期表示値:

- 明るさ: 6
- コントラスト: 122

## 9. ディザ

- 設定行 + Switchとして表示する。
- ラベル: `ディザ`
- 初期値: ON
- 行全体が十分なタップ領域を持つこと。

## 10. 詳細設定・診断

通常時は折りたたみ、必要時のみ展開する。

含める機能:

- ログ同期
- ADB手順
- 診断・注意事項

補助機能は主操作より弱い視覚階層とする。

## 11. 主操作

開始・停止を同時に2つの主要ボタンとして表示しない。

- 停止中: `フィルター開始`
- 実行中: `停止`

同一位置・同一主ボタンを状態で切り替える。

開始操作時には、現在選択されている表示モード・解像度・明るさ・コントラスト・ディザを既存処理へ渡す。

## 12. ステータス

既存処理が出す状態メッセージをCompose UIへ表示する。

例:

- 停止中
- 通知を許可してください
- ユーザー補助を有効にしてください
- ユーザー補助サービスの接続待ち
- キャプチャ開始
- 停止しました
- ログ同期結果

状態はUI内部だけで推測せず、既存Java処理から通知された実状態を優先する。

## 13. プレビュー

Expanded画面では左ペインに静的なGB 160×144風プレビューを表示する。

目的は設定結果の概念提示であり、MediaProjectionのライブ映像をこの仕様では要求しない。

最低限、以下を表示する。

- `GAME BOY`
- 数字行
- 英字行
- GB(DMG) 4階調パレット 0 / 1 / 2 / 3

## 14. スクロールとInsets

- 本文は縦スクロール可能。
- Android 15以降のedge-to-edgeを前提にする。
- `Scaffold` / `WindowInsets` を用いてTopAppBar、本文、主ボタンがstatus/navigation barに隠れないこと。
- 3ボタンナビゲーションでも操作可能であること。

## 15. アクセシビリティ

- 文字サイズ拡大時に重要操作が切れない。
- 200%相当のフォントスケールでも縦スクロールにより全項目へ到達可能であること。
- すべての主要操作に意味のあるsemantics / contentDescriptionを持たせる。
- 色だけで状態を表現しない。
- タッチターゲットはMaterialの標準最小サイズを下回らない。

## 16. テーマ

- Material 3を使用する。
- Light / Darkの両方で読めること。
- Dynamic Colorが利用可能な端末では適用可能とする。
- ただしGBプレビューのDMGパレットはテーマ色に追従させず、固定表示とする。

## 17. アーキテクチャ

- 既存Javaのフィルター・MediaProjection・Accessibility・ログ・フォント処理を維持する。
- Composeは操作画面だけを担当する。
- JavaとComposeの間に明示的なUI bridge/stateを設ける。
- 既存処理からの状態更新をComposeへ伝達できること。
- Compose側の選択値を開始時に既存Java処理へ渡せること。

## 18. 依存関係 / Build条件（2026-08-20調査値）

安定版を優先する。

- Compose BOM: `2026.08.00`
- Compose core: 1.12系（BOM管理）
- Material 3: `1.4.0`
- Activity Compose: `1.13.0`
- Material 3 Adaptive: `1.3.0`
- compileSdk: `37`
- targetSdk: `35`を維持（UI移行でtarget動作まで変更しない）
- AGP: `9.2.1`を採用可能な安定9.2系として使用
- Gradle: `9.4.1`
- JDK: `17`
- Compose Compiler plugin / Kotlin: `2.3.21`

AGP 9以降のbuilt-in Kotlinを使用し、`org.jetbrains.kotlin.android` pluginは追加しない。Compose compiler pluginは別途適用する。

## 19. 非対象

このUI改修では以下を変更しない。

- フィルターアルゴリズム
- キャプチャ方式
- 性能フレームレート
- font_min / 日本語8×8フォント
- Accessibilityでの文字抽出ルール
- ログフォーマット
- 署名方式

## 20. 完了条件

- 本仕様に対応する試験表が全項目PASS。
- 既存のfont_min基準テスト、日本語レンダラテストが退行しない。
- Debug APKがCIで生成される。
- PhoneとExpandedの両レイアウトがコード上で成立する。
- UI操作から既存開始/停止/ログ/ADB処理へ到達できる。
