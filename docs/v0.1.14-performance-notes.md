# GBModer v0.1.14 performance path

Android 14+ window capture now prepares a GPU path for GB, GBA, and DS display modes:

- wrap the screenshot HardwareBuffer as a hardware Bitmap without copying it to a software Bitmap
- quantize the requested output resolution in an AGSL RuntimeShader
- apply GB palette / RGB555 / RGB666 and ordered dithering in the GPU draw path
- request the next screenshot immediately after a successful GPU submission; use a 120 ms backoff when Android reports that screenshot requests are too frequent
- keep the existing CPU path for GBC because its visible 56-color reduction is frame-global rather than per-pixel
- disable the GPU path and fall back to CPU if the renderer throws

Performance logs identify GPU frames with `render_path=gpu_hardware` and include `hardware_wrap_ms`; the legacy `bitmap_copy_ms`, `downsample_ms`, and `filter_ms` fields are written as 0 for those frames because those CPU stages are bypassed.
